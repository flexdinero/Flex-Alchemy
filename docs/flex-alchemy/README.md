# Flex Alchemy — research and system blueprint

**Version:** 2.0 · **Research cutoff:** November 4, 2026 · **Status:** proposed architecture and requirements; not an implemented platform.

Flex Alchemy turns a founder's intent into verified, operating technology through persistent coordination, reusable skills, controlled execution, independent checks, and continuous improvement. The founder directs outcomes; Alchemy manages the technical work and presents evidence.

This package consolidates the Alchemy discussion supplied in this conversation and expands it with current primary-source research. It preserves the ambition to support advanced technology beyond websites, while making scope, permissions, evidence, cost, and unresolved limitations explicit. It does not claim to have recovered other conversations or read every ecosystem document. No external project blueprint is silently treated as authoritative.

## Central decisions

1. Build a persistent control system around interchangeable models and runtimes.
2. Treat skills as versioned, evaluated software dependencies, not magic prompts.
3. Automate within a defined operating envelope; broaden that envelope only after evidence supports it.
4. Separate the builder, the verifier, and the authority that permits consequential actions.
5. Own the project state, requirements, evaluation corpus, skill registry, and outcome evidence.
6. Retrieve changing knowledge; encode reusable procedures in skills; train weights only for demonstrated behavior or cost gaps.
7. Deliver one complete, recoverable journey before expanding into many specialties.
8. Preserve the entire product vision as a traceable backlog; never silently discard difficult requirements.

## What is complete in this delivery

The research synthesis, architecture specification, command design, operational policies, model strategy, requirements coverage, and reusable master prompt are documented. The existing repository README is preserved. These files do not install skills, start background agents, train models, deploy software, or establish production security controls.

The intended quality promise is **verified completion within a declared scope, with visible uncertainty and recoverable failures**. No prompt, model, benchmark, or architecture establishes universal perfection, zero defects, unlimited capability, or certainty about unknown requirements.

Source references such as **S01** resolve in [the source register](08-research-sources.md). Vendor observations are distinguished from Alchemy design recommendations. Research is a broad architecture sweep, not an exhaustive audit of every technology, legal jurisdiction, or scientific field.
